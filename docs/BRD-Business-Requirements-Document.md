## 1. ملخص تنفيذي (Executive Summary)

منصة **شجرة العائلة الكبرى** هي تطبيق ويب تفاعلي تشاركي مبني بتقنية Next.js 14، يتيح لجميع أفراد العائلة المساهمة الجماعية في بناء وتوثيق شجرة الأنساب العائلية على كانفاس تفاعلي لا نهائي (Infinite Canvas). يتميز التطبيق بنظام حوكمة واعتماد صارم حيث لا تُدرج أي إضافة جديدة بالشجرة الرسمية إلا بعد مراجعتها واعتمادها من مشرفي الفروع (Branch Stewards)، مع محرك ذكاء لكشف التكرارات ومنع الحلقات النسبية الدائرية.

## 2. أهداف المشروع (Business Objectives)

### 2.1 الأهداف الرئيسية
| # | الهدف | الوصف |
|---|-------|-------|
| O-1 | **التكاتف التشاركي** | تمكين جميع أفراد العائلة من إدخال بيانات الأقارب وربط صلات النسب بشكل جماعي تعاوني |
| O-2 | **حوكمة لجنة الاعتماد** | ضمان صحة ودقة الأنساب عبر نظام مراجعة واعتماد رسمي من مشرفي الفروع |
| O-3 | **حفظ التراث والأنساب** | توثيق رقمي دائم للسير الشخصية والأصول النسبية لتعرف عليه الأجيال القادمة |
| O-4 | **منع التكرارات والتضاربات** | خوارزمية ذكية لاكتشاف السجلات المكررة وتوحيدها تلقائياً |
| O-5 | **سلامة البيانات النسبية** | منع الحلقات الدائرية في شجرة النسب (Circular Kinship Loop Prevention) |

### 2.2 مؤشرات النجاح (KPIs)
- دقة الأنساب: 100% (كل علاقة تمر بعملية اعتماد)
- النظام تشاركي: مفتوح لجميع أفراد العائلة
- الحفظ التلقائي: كل تعديل يُحفظ مباشرة في قاعدة بيانات PostgreSQL

## 3. أصحاب المصلحة والأدوار (Stakeholders & Roles)

### 3.1 أدوار النظام المُنفَّذة فعلياً

| الدور | الرمز في النظام | الصلاحيات الفعلية |
|-------|----------------|-------------------|
| **عضو عائلة (User)** | `USER` / `USR` | إضافة أفراد جدد، ربط علاقات نسبية، تعديل البيانات التي أنشأها، المطالبة بملفه الشخصي، تصفح الشجرة الكاملة |
| **ناظر فرع / مراجع (Reviewer)** | `REVIEWER` / `REV` | كل صلاحيات المستخدم + اعتماد/رفض العلاقات المعلقة، تنفيذ دمج السجلات المكررة، تعديل أي بطاقة في فرعه، الاعتماد التلقائي لإضافاته |
| **مدير النظام (Admin)** | `ADMIN` / `ADM` | كل صلاحيات المراجع + إدارة كاملة للنظام، تعيين مشرفي الفروع، حذف أي سجل |

### 3.2 المستخدمون المستهدفون
- جميع أفراد العائلة بمختلف الأعمار والخبرات التقنية
- مشرفو الفروع العائلية (كبار السن أو المعنيون بالنسب)
- مدير النظام التقني

## 4. المتطلبات الوظيفية (Functional Requirements)

### FR-1: إدارة الأشخاص (Person Management)

|---|---------|----------|--------|
| FR-1.1 | إضافة شخص جذر (Root Person) | إضافة أول شخص في الشجرة بدون ربطه بأحد | ✅ مُنفَّذ |
| FR-1.2 | إضافة قريب مرتبط | إضافة شخص جديد وربطه بشخص موجود (أب/أم/ابن/ابنة) | ✅ مُنفَّذ |
| FR-1.3 | ربط شخص موجود | ربط شخصين موجودين في الشجرة بعلاقة نسبية | ✅ مُنفَّذ |
| FR-1.4 | تعديل بيانات الشخص | تحديث الاسم، الجنس، سنة الميلاد، حالة الحياة، تاريخ الوفاة، مكان الدفن، السيرة الذاتية، الصورة | ✅ مُنفَّذ |
| FR-1.5 | حذف شخص | حذف بطاقة الشخص وجميع علاقاته المرتبطة تلقائياً (CASCADE) | ✅ مُنفَّذ |
| FR-1.6 | إضافة أخ/أخت (Sibling Bridging) | إنشاء تلقائي لعقدة والد مشترك (Placeholder Parent) عند إضافة أخ مع ربط الإخوة تحته | ✅ مُنفَّذ |
| FR-1.7 | بيانات الشخص الكاملة | الاسم الرباعي (الأول، الأب، الجد، العائلة)، الجنس، حالة الحياة، سنة الميلاد، تاريخ الوفاة، مكان الدفن، الصورة، السيرة الذاتية، علامة Placeholder | ✅ مُنفَّذ |

## 5. المتطلبات غير الوظيفية (Non-Functional Requirements)

### NFR-1: الأداء
| # | المتطلب | التفاصيل |
|---|---------|----------|
| NFR-1.1 | Viewport Culling | تحميل العقد المرئية فقط عبر معاملات xMin/yMin/xMax/yMax |

| NFR-1.3 | Force Dynamic | تعطيل التخزين المؤقت لـ API الكانفاس لضمان البيانات الحية |

### NFR-2: المرونة والمتانة
| # | المتطلب | التفاصيل |
|---|---------|----------|
| NFR-2.1 | Dual Storage Fallback | كل عملية كتابة تحاول PostgreSQL أولاً ثم تتراجع لـ MemoryStore |
| NFR-2.2 | Photo Upload Fallback | محاولة رفع Supabase Storage أولاً ثم ضغط Base64 كبديل |
| NFR-2.3 | Auth Fallback | محاولة Supabase Auth أولاً ثم التراجع للمصادقة المحلية |

### NFR-3: الأمان
| # | المتطلب | التفاصيل |
|---|---------|----------|
| NFR-3.1 | RBAC | التحكم بالوصول بناءً على الأدوار (User/Reviewer/Admin) |
| NFR-3.2 | Ownership Check | التحقق من ملكية الشخص قبل التعديل (المُنشئ أو صاحب الملف أو المراجع) |
| NFR-3.3 | RLS Policies | سياسات أمان على مستوى الصفوف في PostgreSQL (مُعدّة ولم تُفعّل بالكامل) |
| NFR-3.4 | Auth Trigger | مزامنة تلقائية بين auth.users و public.users عبر PostgreSQL Trigger |
