## 1. الممثلون (Actors)

| الممثل | الرمز | الوصف |
|--------|-------|-------|
| **عضو العائلة** | `USER` | أي فرد من أفراد العائلة مسجل في النظام |
| **ناظر الفرع (المراجع)** | `REVIEWER` | مشرف معتمد مسؤول عن مراجعة واعتماد إضافات فرعه |
| **مدير النظام** | `ADMIN` | المسؤول الأعلى عن النظام بالكامل |
| **زائر (غير مسجل)** | `VISITOR` | متصفح لم يسجل دخوله بعد |

## 2. قصص المستخدمين (User Stories)

### الملحمة 1: التسجيل والمصادقة (Epic: Authentication)

#### US-1.1: تسجيل حساب جديد
**بصفتي** زائراً جديداً للمنصة
**أريد** إنشاء حساب بالبريد الإلكتروني واسمي الكامل
**حتى** أتمكن من المساهمة في بناء شجرة العائلة

**معايير القبول:**
- [x] يمكنني إدخال: البريد الإلكتروني، الاسم الكامل، رقم الهاتف (اختياري)
- [x] النظام يتحقق من عدم تكرار البريد الإلكتروني
- [x] يتم إنشاء الحساب بدور `USER` تلقائياً
- [x] يتم تسجيل دخولي تلقائياً بعد التسجيل
- [x] تظهر رسالة نجاح باللغة العربية

**الواجهات المعنية:** `AuthModal.tsx`
**API:** `POST /api/v1/auth/register`

---

#### US-1.2: تسجيل الدخول
**بصفتي** عضواً مسجلاً في العائلة
**أريد** تسجيل الدخول بالبريد الإلكتروني
**حتى** أتمكن من الوصول لصلاحياتي في النظام

**معايير القبول:**
- [x] يمكنني الدخول بالبريد الإلكتروني فقط (الوضع المحلي)
- [x] يمكنني الدخول عبر Supabase Auth (البريد + كلمة المرور) إن كان مُهيأً
- [x] إذا فشل Supabase Auth، يتم التراجع للدخول المحلي تلقائياً
- [x] إذا لم يكن البريد مسجلاً، يتم إنشاء حساب تلقائياً
- [x] يتم حفظ الجلسة في المتصفح (localStorage)
- [x] تظهر رسالة خطأ بالعربية عند فشل الدخول

**الواجهات المعنية:** `AuthModal.tsx`, `AuthContext.tsx`

---

#### US-1.3: تسجيل الخروج
**بصفتي** مستخدماً مسجلاً في النظام
**أريد** تسجيل الخروج من حسابي
**حتى** أحمي خصوصية حسابي على الأجهزة المشتركة

**معايير القبول:**
- [x] يتم مسح بيانات الجلسة من localStorage
- [x] يتم مسح جلسة Supabase Auth إن وجدت
- [x] يتم إعادة تعيين حالة المصادقة (user, session, dbUser, role)
- [x] يظهر زر "تسجيل الدخول / حساب جديد" بعد الخروج

**الواجهات المعنية:** `Navbar.tsx`, `AuthContext.tsx`

---

#### US-1.4: عرض معلومات الحساب
**بصفتي** مستخدماً مسجلاً
**أريد** رؤية اسمي ودوري في شريط التنقل
**حتى** أعرف أنني مسجل الدخول بالحساب الصحيح

**معايير القبول:**
- [x] يظهر الحرف الأول من اسمي في دائرة ملونة
- [x] يظهر اسمي الكامل بجانب الأيقونة
- [x] يظهر وصف الدور: "عضو عائلة" / "ناظر فرع (راجع)" / "مدير النظام"
- [x] تظهر على الشاشات الكبيرة فقط (مخفية على الهواتف)

**الواجهات المعنية:** `Navbar.tsx`

### الملحمة 2: إدارة أفراد الشجرة (Epic: Person Management)

#### US-2.1: إضافة الجد الأول / الشخص الجذر
**بصفتي** عضواً في العائلة
**أريد** إضافة أول شخص في الشجرة (الجد الأعلى)
**حتى** يكون الأساس الذي تُبنى عليه الشجرة

**معايير القبول:**
- [x] يمكنني إضافة شخص بدون ربطه بأحد (Root Person)
- [x] الحقول الإلزامية: الاسم الأول والجنس
- [x] الحقول الاختيارية: اسم الأب، اسم الجد، اسم العائلة، سنة الميلاد، حالة الحياة، تاريخ الوفاة، مكان الدفن، صورة
- [x] يظهر الشخص كعقدة على الكانفاس فوراً
- [x] تظهر رسالة "تم إضافة الجد/الشخص الأول في شجرة العائلة بنجاح!"

**الواجهات المعنية:** `AddRelationModal.tsx`, `FamilyTreeCanvas.tsx`
**API:** `POST /api/v1/persons` (بدون `related_person_id`)

---

#### US-2.2: إضافة ابن/ابنة لشخص موجود
**بصفتي** عضواً في العائلة
**أريد** إضافة ابن أو ابنة لشخص موجود في الشجرة
**حتى** أوثق الجيل التالي من العائلة

**معايير القبول:**
- [x] أنقر على زر (+) أسفل بطاقة الشخص
- [x] تظهر نافذة إضافة مع نوع العلاقة "ابن/ابنة" مُحدد مسبقاً
- [x] أدخل بيانات الابن/الابنة
- [x] يتم فحص التكرارات في الوقت الحقيقي أثناء الكتابة
- [x] إذا كنت مراجعاً: العلاقة تُعتمد تلقائياً (VERIFIED)
- [x] إذا كنت عضواً: العلاقة تبقى معلقة (PENDING) حتى الاعتماد
- [x] يظهر النظام تحذيراً إذا اكتشف حلقة نسب دائرية (HTTP 422)

**الواجهات المعنية:** `PersonNode.tsx` (زر +), `AddRelationModal.tsx`
**API:** `POST /api/v1/persons` (مع `related_person_id` + `relationship_type`)

---

#### US-2.3: إضافة أب/أم لشخص موجود
**بصفتي** عضواً في العائلة
**أريد** إضافة والد أو والدة لشخص موجود في الشجرة
**حتى** أوثق الجيل السابق وأرتقي بالشجرة لأعلى

**معايير القبول:**
- [x] أنقر على زر (+) أعلى بطاقة الشخص
- [x] تظهر نافذة إضافة مع نوع العلاقة "أب/أم" مُحدد مسبقاً
- [x] يتم فحص الحلقات الدائرية قبل الإضافة
- [x] يظهر الوالد الجديد كعقدة فوق الشخص على الكانفاس

**الواجهات المعنية:** `PersonNode.tsx`, `AddRelationModal.tsx`
**API:** `POST /api/v1/persons`

---

#### US-2.4: إضافة أخ/أخت (Sibling Bridging)
**بصفتي** عضواً في العائلة
**أريد** إضافة أخ أو أخت لشخص موجود
**حتى** أوثق الإخوة في نفس الجيل

**معايير القبول:**
- [x] أختار نوع العلاقة "أخ/أخت" أو وضع `AUTO_PARENT_BRIDGE`
- [x] إذا كان للشخص والد موجود في الشجرة → ربط الأخ مباشرة كابن للوالد
- [x] إذا لم يكن هناك والد → إنشاء عقدة والد مؤقتة (Placeholder) تلقائياً
- [x] العقدة المؤقتة تأخذ اسم الأب من بيانات الشخص الأصلي
- [x] العقدة المؤقتة مُعلَّمة بـ `is_placeholder = true`
- [x] ربط كلا الشخصين كأبناء للوالد المشترك
- [x] تظهر رسالة "تم ربط الإخوة بنجاح وإنشاء الوالد المشترك بالشجرة!"

**الواجهات المعنية:** `AddRelationModal.tsx`
**API:** `POST /api/v1/persons` (Phase 1: Sibling Bridging)

---

#### US-2.5: ربط شخصين موجودين بعلاقة
**بصفتي** عضواً في العائلة
**أريد** ربط شخصين موجودين في الشجرة بعلاقة نسبية
**حتى** أوصل بين فروع العائلة المنفصلة

**معايير القبول:**
- [x] أختار الشخص الأول والثاني من قائمة البحث
- [x] أحدد نوع العلاقة (أب/أم، ابن/ابنة، أخ/أخت)
- [x] يتم فحص الحلقات الدائرية قبل الربط
- [x] تظهر رسالة "تم ربط العلاقة مع الشخص الموجود في شجرة العائلة بنجاح!"

**الواجهات المعنية:** `LinkNodesModal.tsx`
**API:** `POST /api/v1/persons` (Phase 2: Link Existing)

---

#### US-2.6: تعديل بيانات شخص
**بصفتي** عضواً في العائلة (المُنشئ أو صاحب الملف أو المراجع)
**أريد** تعديل بيانات شخص موجود في الشجرة
**حتى** أصحح المعلومات أو أضيف تفاصيل ناقصة

**معايير القبول:**
- [x] أنقر على أيقونة القلم (✏️) في بطاقة الشخص
- [x] تظهر نافذة تعديل مع جميع البيانات القابلة للتعديل
- [x] يمكنني تعديل: الاسم، الجنس، سنة الميلاد، حالة الحياة، تاريخ الوفاة، مكان الدفن، السيرة، الصورة
- [x] **التحقق من الصلاحيات:** فقط المُنشئ أو صاحب الملف أو المراجع/المدير يحق لهم التعديل
- [x] تظهر رسالة HTTP 403 مع شرح بالعربية إذا لم يكن لدي صلاحية
- [x] تظهر رسالة "تم تحديث بيانات الشخص بنجاح" عند النجاح

**الواجهات المعنية:** `EditPersonModal.tsx`
**API:** `PUT /api/v1/persons`

---

#### US-2.7: حذف شخص من الشجرة
**بصفتي** عضواً مصرحاً
**أريد** حذف شخص من الشجرة
**حتى** أزيل السجلات الخاطئة

**معايير القبول:**
- [x] يتم حذف جميع العلاقات المرتبطة بالشخص تلقائياً (CASCADE)
- [x] يتم الحذف من قاعدة البيانات والذاكرة معاً
- [x] تظهر رسالة "تم حذف بطاقة الشخص من الشجرة بنجاح"

**API:** `DELETE /api/v1/persons?id=`

### الملحمة 3: نظام الزواج والأزواج (Epic: Marriage System)

#### US-3.1: إضافة زوج/زوجة من داخل الشجرة
**بصفتي** عضواً في العائلة
**أريد** تسجيل زواج بين شخصين موجودين في الشجرة
**حتى** أوثق العلاقات الزوجية

**معايير القبول:**
- [x] أنقر على زر (+) يسار بطاقة الشخص أو زر "إضافة" في قسم الزوجات
- [x] يمكنني البحث عن زوجة موجودة في الشجرة وربطها
- [x] يتم إنشاء سجل في جدول `marriages` مع `wife_id` محدد
- [x] يظهر اسم الزوجة في بطاقة الزوج والعكس
- [x] يمكنني النقر على اسم الزوجة للتركيز على بطاقتها

**الواجهات المعنية:** `AddSpouseModal.tsx`, `PersonNode.tsx`
**API:** `POST /api/v1/marriages`

---

#### US-3.2: إضافة زوجة خارجية (من خارج الشجرة)
**بصفتي** عضواً في العائلة
**أريد** تسجيل زواج بزوجة من عائلة أخرى غير مسجلة في الشجرة
**حتى** أوثق جميع الزيجات حتى لو لم تكن الزوجة من العائلة

**معايير القبول:**
- [x] يمكنني إدخال اسم الزوجة الخارجية واسم عائلتها
- [x] يتم حفظها في حقول `external_spouse_name` و `external_family_name`
- [x] لا يتم إنشاء عقدة جديدة في الشجرة
- [x] يظهر اسمها في بطاقة الزوج بدون إمكانية النقر للتركيز

---

#### US-3.3: تعدد الزوجات
**بصفتي** عضواً في العائلة
**أريد** تسجيل أكثر من زوجة لنفس الشخص
**حتى** أوثق جميع الزيجات بترتيبها

**معايير القبول:**
- [x] يمكن تسجيل عدة زوجات مع تحديد ترتيب الزواج (الأولى، الثانية...)
- [x] كل زواج له حالة مستقلة: `ACTIVE` / `DIVORCED` / `DECEASED`
- [x] تظهر جميع الزوجات في قسم الأزواج ببطاقة الشخص
- [x] تظهر رموز الحالة: 💚 (قائم)، 💔 (مطلقة)، 🖤 (متوفاة)

### الملحمة 4: نظام المراجعة والاعتماد (Epic: Review & Approval)

#### US-4.1: فتح لوحة المراجع
**بصفتي** ناظر فرع (مراجع)
**أريد** فتح لوحة المراجعة الخاصة بي
**حتى** أرى العلاقات المعلقة وطلبات الدمج

**معايير القبول:**
- [x] أنقر على أيقونة الدرع (🛡️) في شريط التنقل
- [x] تظهر لوحة مراجعة بتبويبين: "طلبات العلاقات المعلقة" و "أداة دمج المكررات"
- [x] يظهر عدد العناصر المعلقة بجانب كل تبويب

**الواجهات المعنية:** `StewardDashboard.tsx`

---

#### US-4.2: اعتماد علاقة معلقة
**بصفتي** ناظر فرع
**أريد** اعتماد علاقة نسبية معلقة
**حتى** تُدرج رسمياً في الشجرة المعتمدة

**معايير القبول:**
- [x] أرى تفاصيل العلاقة: الاسم الرباعي لكلا الطرفين + نوع العلاقة
- [x] أرى تاريخ تقديم الطلب ومقدم الطلب
- [x] أضغط "اعتماد (VERIFIED)" لتحويل الحالة إلى مُعتمد
- [x] يتم تسجيل معرف المراجع وتاريخ الاعتماد
- [x] يتحول خط الاتصال من متقطع أصفر إلى أخضر متصل

**API:** `PUT /api/v1/review/approve` مع `action: 'approve'`

---

#### US-4.3: رفض علاقة معلقة
**بصفتي** ناظر فرع
**أريد** رفض علاقة نسبية غير صحيحة
**حتى** أحمي دقة الشجرة

**معايير القبول:**
- [x] أضغط "رفض" لتحويل الحالة إلى REJECTED
- [x] العلاقة المرفوضة لا تظهر في الكانفاس
- [x] تظهر رسالة "تم رفض العلاقة المعلقة"

**API:** `PUT /api/v1/review/approve` مع `action: 'reject'`

---

#### US-4.4: الاعتماد التلقائي للمراجعين
**بصفتي** ناظر فرع أو مدير
**أريد** أن تُعتمد إضافاتي تلقائياً بدون مراجعة
**حتى** أستطيع بناء الشجرة بكفاءة أعلى

**معايير القبول:**
- [x] إذا كان role = 'REVIEWER' أو 'ADMIN' → العلاقة تحصل على status = 'VERIFIED' فوراً
- [x] يتم تسجيل المراجع والتاريخ تلقائياً
- [x] لا تظهر في قائمة المعلقات

---

### الملحمة 5: كشف التكرارات والدمج (Epic: Deduplication)

#### US-5.1: فحص التكرارات في الوقت الحقيقي
**بصفتي** عضواً يضيف شخصاً جديداً
**أريد** أن يحذرني النظام إذا كان الشخص موجوداً مسبقاً
**حتى** لا أنشئ سجلات مكررة

**معايير القبول:**
- [x] أثناء كتابة الاسم في نافذة الإضافة، يتم فحص التكرارات تلقائياً
- [x] إذا وُجد تطابق بنسبة ≥55%، يظهر تنبيه بالسجلات المشابهة
- [x] يعرض النظام نسبة التطابق ومكوناته (اسم، سياق، سنة ميلاد)
- [x] يمكنني تجاهل التنبيه والمتابعة أو طلب الدمج

**الواجهات المعنية:** `AddRelationModal.tsx`
**API:** `POST /api/v1/dedup/check`

---

#### US-5.2: تنفيذ دمج سجلات مكررة
**بصفتي** ناظر فرع
**أريد** دمج سجلين مكررين في سجل واحد
**حتى** أوحد البيانات وأمنع التضارب

**معايير القبول:**
- [x] أرى مقارنة جنباً إلى جنب (Side-by-Side) بين السجل الأساسي والمكرر
- [x] أرى الاسم الرباعي وسنة الميلاد والسيرة لكل سجل
- [x] أضغط "تنفيذ الدمج الآن"
- [x] يتم نقل جميع علاقات السجل المكرر للسجل الأساسي
- [x] يتم حذف السجل المكرر نهائياً
- [x] تظهر رسالة "تم دمج السجل المكرر بنجاح"

**الواجهات المعنية:** `StewardDashboard.tsx` (تبويب الدمج)
**API:** `POST /api/v1/review/merge`

---

### الملحمة 6: حذف العلاقات (Epic: Relationship Deletion)

#### US-6.1: حذف علاقة مع تنظيف تلقائي
**بصفتي** عضواً (منشئ العلاقة) أو مراجعاً
**أريد** حذف علاقة نسبية خاطئة
**حتى** أصحح بنية الشجرة

**معايير القبول:**
- [x] فقط منشئ العلاقة أو المراجع/المدير يحق لهم الحذف
- [x] يتم التحقق من الصلاحيات قبل الحذف (RBAC)
- [x] بعد الحذف: إذا كان أحد الطرفين عقدة Placeholder بدون علاقات متبقية → حذفها تلقائياً (Orphan Cleanup)
- [x] تظهر رسالة خطأ HTTP 403 إذا لم يكن لدي صلاحية
- [x] تظهر رسالة "تم حذف العلاقة بنجاح وتنظيف العقد اليتيمة"

**الواجهات المعنية:** `DeleteRelationModal.tsx`
**API:** `DELETE /api/v1/relationships`

### الملحمة 7: المطالبة بالملف الشخصي (Epic: Profile Claiming)

#### US-7.1: المطالبة بملفي في الشجرة ("هذا أنا")
**بصفتي** عضواً في العائلة
**أريد** ربط حسابي ببطاقتي الموجودة في الشجرة
**حتى** أتمكن من تعديل بياناتي الشخصية مباشرة

**معايير القبول:**
- [x] أجد بطاقتي في الشجرة وأنقر "هذا أنا (مطالبة بالملف)"
- [x] تظهر نافذة تأكيد المطالبة
- [x] إذا لم يطالب أحد بالملف سابقاً → يتم ربط حسابي بالبطاقة

### UC-1: إضافة فرد جديد للشجرة (Use Case: Add Person to Tree)

```
الممثل الرئيسي: عضو العائلة (USER)
الشرط المسبق: المستخدم مسجل الدخول، الشجرة تحتوي على شخص واحد على الأقل
المسار الأساسي:
  1. المستخدم ينقر على زر (+) في بطاقة شخص موجود
  2. تظهر نافذة إضافة مع نوع العلاقة مُحدد مسبقاً
  3. المستخدم يدخل بيانات الشخص الجديد
  4. النظام يفحص التكرارات في الوقت الحقيقي
  5. النظام يفحص الحلقات الدائرية
  6. النظام ينشئ الشخص والعلاقة
  7. البطاقة الجديدة تظهر على الكانفاس

المسار البديل A — تكرار مكتشف:
  4a. النظام يعرض تنبيه تكرار مع نسبة التطابق
  4b. المستخدم يختار "متابعة" أو "إلغاء"

المسار البديل B — حلقة دائرية:
  5a. النظام يعرض خطأ HTTP 422 بالعربية
  5b. العملية تُلغى ولا يتم إنشاء أي سجل

المسار البديل C — إضافة أخ (Sibling):
  3a. المستخدم يختار نوع "أخ/أخت"
  6a. النظام يبحث عن والد مشترك
  6b. إن لم يوجد → إنشاء عقدة والد Placeholder
  6c. ربط الإخوة تحت الوالد المشترك

الشرط اللاحق:
  - الشخص الجديد موجود في قاعدة البيانات
  - العلاقة مُنشأة بحالة VERIFIED (للمراجعين) أو PENDING (للأعضاء)
```

### UC-2: مراجعة واعتماد العلاقات (Use Case: Review & Approve Relationships)

```
الممثل الرئيسي: ناظر الفرع (REVIEWER)
الشرط المسبق: توجد علاقات بحالة PENDING
المسار الأساسي:
  1. المراجع ينقر على أيقونة الدرع في شريط التنقل
  2. تظهر لوحة المراجعة مع قائمة العلاقات المعلقة
  3. المراجع يراجع الاسم الرباعي لكلا الطرفين ونوع العلاقة
  4. المراجع ينقر "اعتماد (VERIFIED)"
  5. النظام يحدث حالة العلاقة في PostgreSQL
  6. الخط المتقطع يتحول لأخضر متصل على الكانفاس

المسار البديل — رفض:
  4a. المراجع ينقر "رفض"
  5a. حالة العلاقة تتحول إلى REJECTED
  6a. العلاقة تختفي من الكانفاس
```

### UC-3: كشف الجد المشترك (Use Case: Find Common Ancestor)

```
الممثل الرئيسي: أي مستخدم
الشرط المسبق: الشجرة تحتوي على أشخاص مرتبطين بعلاقات
المسار الأساسي:
  1. المستخدم يفتح صفحة /common-ancestor
  2. المستخدم يبحث عن الشخص الأول ويحدده
  3. المستخدم يبحث عن الشخص الثاني ويحدده
  4. النظام يحسب المسار من كل شخص للجذر
  5. النظام يجد أول عقدة مشتركة (LCA)
  6. النظام يحسب المسافة من كل شخص للجد المشترك
  7. النظام يعرض:
     - رسم Y-Shape مع المسارين
     - الجد المشترك ببطاقة ذهبية مع تاج
     - درجة القرابة بالعربية

المسار البديل A — نفس الشخص:
  3a. المستخدم يختار نفس الشخص في كلا الحقلين
  4a. النظام يعرض رسالة "تم اختيار نفس الشخص في الحقلين"

المسار البديل B — لا يوجد جد مشترك:
  5a. لا توجد عقدة مشتركة في المسارين
  6a. النظام يعرض "لا يوجد جد مشترك مسجل بين (X) و (Y) في السجلات حالياً"
```

### UC-4: دمج السجلات المكررة (Use Case: Merge Duplicate Records)

```
الممثل الرئيسي: ناظر الفرع (REVIEWER)
الشرط المسبق: يوجد طلب دمج بحالة PENDING
المسار الأساسي:
  1. المراجع يفتح لوحة المراجعة → تبويب "أداة دمج المكررات"
  2. المراجع يرى مقارنة Side-by-Side بين السجلين
  3. المراجع يتأكد أن السجلين فعلاً لنفس الشخص
  4. المراجع ينقر "تنفيذ الدمج الآن"
  5. النظام ينقل جميع علاقات السجل المكرر للسجل الأساسي
  6. النظام يحذف السجل المكرر نهائياً
  7. النظام يحدث حالة طلب الدمج إلى APPROVED

الشرط اللاحق:
  - السجل المكرر محذوف
  - جميع علاقاته منقولة للسجل الأساسي
  - لا يوجد أي فقدان للبيانات العلائقية
```
